# Production runtime dependencies for the SEIS AI Service.
#
# Scope is deliberately limited to what Week 2 (AI Service Foundation)
# needs: the FastAPI runtime, typed config, structured logging, resilience
# helpers, and a connection-only client for Gemini (§10, §11 — no
# embedding-model or LLM-generation libraries yet; those land with the
# Repository Processing Engine and RAG pipeline in Weeks 3-4, §25).
#
# ChromaDB is intentionally NOT listed here — see requirements-vectorstore.txt
# and the "Local Environment vs. Container Environment" note in the Task 2
# writeup for why it is installed only inside the Linux container (Task 14),
# not in the native Windows venv.
#
# redis (Task 10), unlike chromadb, IS listed here: redis-py is pure
# Python with no native/C-extension build step, so it installs cleanly
# in the native Windows venv. Only the Redis *server* needs Docker
# (ADR-005) — the client library does not.
#
# celery (Task 11): configures the task-queue application object only --
# this task does not run a worker process. The historical Windows
# limitation is the *worker's* default prefork (multiprocessing) pool,
# not the client/producer side used here, so the package installs and
# the app configures/connects cleanly in this native Windows venv.
#
# Pinned to exact versions verified against Python 3.13.4 in this
# environment. Bump deliberately, one dependency at a time, re-running the
# test suite (§27 Testing) after each bump.
